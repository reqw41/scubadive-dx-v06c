## 2. Запутанная логика (глобалы, дубли, контракты)

- `blue_this` (`scubacod1.asm:265`): значения 0/1 читает только мёртвый BLUEWRITE, живо лишь «2 = лодка». `blit_w` дублирует `(IY+$0E)`. Снять оба.
- `blue_on`: 5 писателей, 1 сбрасыватель (начало DrawGameScr), липкий до перерисовки — допустимо, но инвариант нигде не записан.
- `shell_ink`: живой, контракт понятен; `il_a`/`il_hl`/`DiverObj+$23` как временные — ~100–175 Б мёртвых пар «сохранил и тут же затёр» (перечень в отчётах B/C: CopyRecordsFwd/Bck по 26 тактов на запись, LBEDB ×8, LE682, LB53A, z80_ldar, DrawGameScr ×12, MiniMap_Addr ×9, PrintDec SLA C, PrintString…).
- Бронь пула 13..15 (`LBEC7`): комментарий про «колесо таймеров» (не реализовано, docs/node_timer_wheel.md), фактические жильцы — кадр лодки 0xBD00, модуль лодки 0xBE00, MENUART 0xBF10; ставится безусловно; три расходящихся объяснения в трёх файлах.
- Четыре имени чистки экрана (ClearScreen = ClearGameScreen / ClearScreenFillAttr / ClearFieldFillAttr); два DecodeKeyboard подряд в цикле меню (KSTATE5 + повторный скан).
- `LB737` (нативный) vs `LB7BB` (лента z80_*) — близнецы Зимина в двух стилях; то же LBE40/LBE6D/LBE9A/LC431 vs LBE58/LBE85/LBEB2/LC45C.
- `LA0F5` оптимизирован вручную, его близнецы в DrawGameScr (105–140) и MiniMap_Addr (582–622, 3344 вызова/6 перерисовок) — нет.
- Три идиомы переключения плоскости (`xor $20` / `add 20h` / `sub 20h`); девять площадок самомодификации операндов (LB500_end, LB4F0_go, SH_b*, SH_row, MenuBigPos) без единого списка.
- `pop hl ;HACK` в MenuFromDemo — держится на единственном вызывающем LEEAD; `pace_tick` портит B сверх контракта.
- `SkillChar` живёт внутри мёртвой строки `StrSkill` (печатается только без MENUHUD).
- `DrawClouds` считает столбцы `and 1Fh/or 0C0h` без FIELD_*: верно только под WIDE.
- `JoystickP` опрашивается каждый кадр в ISR, результат никто не читает; `out (4),88h` тут же перекрыт `out (4),83h`.
- Константы геометрии рассыпаны по четырём файлам (FIELD_*, SKY_TOP, HUDX, BLUE_WATER_LO, POOL_HI, MENU_*); `MenuSkillMark` использует HUDX до INCLUDE файла, где он определён (два прохода спасают).

## 5. Чисто (проверено, проблем нет)

Данных в потоке команд в codc нет; печать за SCRATTR невозможна; гонки за порт 3
нет (пишет только KEYINT); `il_a/il_hl` не трогаются из ISR; PrintDec/HELD и
координаты SKILL/LIVES согласованы между ветками; ни один вызывающий `z80_bit*`
не ветвится по C; ГПСЧ двойное `in (0Bh)` безопасно (KEYINT счётчик 0 не
трогает); ключ кадра лодки сбрасывается единственным писателем SprBoat (LE682);
`(IY+$07)=8` у лодки держится на `(IY+$06)=7` в LC092; `scubadivr`/`scubarelb`
— чистые данные.

## 6. Предлагаемый порядок работ

1. **Дефекты D1, D2, D4, D5** (пул — СДЕЛАНО, EI, ASSERT BOATFAST, LIVES) — по отдельному коммиту, каждый с гейтом: D1 — pool_gate с новым эталоном + state_cmp; D2 — attract_gate; D3 — сборка из чистого клона.
2. **Вырезать мёртвое** (раздел 4) одним-двумя коммитами с проверкой `romdiff`/`state_cmp`: боевой образ байт в байт тот же. Заодно: боевой набор флагов — в `tools/build_prod.sh`.
3. **Снять мёртвую обвязку рекомпилятора** (~300 Б, раздел 2) — по листингу, romdiff по состояниям (образ изменится, состояния нет).
4. **D6** (DrawSurface из цикла) и выбор атрибута в цикле тайлов нативно — ускорение перерисовки, по замеру. Память под вынос модулей из пула даёт п. 3, не атрибутика.
5. **Комментарии** (раздел 3) и инварианты глобалов; единый блок констант геометрии; список площадок самомодификации.
6. **Документ** «что отличается от vector06c-scubadive».
