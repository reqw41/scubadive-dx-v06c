# Звук для Z80-сборки: разведка и смета

Задача: Z80-версия Зимина на Векторе нема. Вернуть ей звук титульной мелодии,
патчем поверх исходника автора, не задев оракул.

## Что найдено

**Бипер заглушён радикально.** `ROM_BEEPER` (`src/scubacod1.asm`) начинается с
`ret ;STUB`, всё тело процедуры ПЗУ Спектрума ниже недостижимо.

**Тело мёртво — доказано прогоном.** Сторож по пяти lockstep-сценариям:

    idle    601 тик:  вызовов ROM_BEEPER 1, заходов в тело 0
    dive    902:      1 / 0
    turn    902:      1 / 0
    level4  901:      6 / 0
    long   2501:      1 / 0
    ИТОГО 5807 тиков, 10 вызовов, заходов в 0x0417..0x042E: 0

Выборка не пуста (вызовы есть), значит вывод действителен: **24 байта тела
переиспользовать можно**. Размер измерен по символам: `ROM_BEEPER` 0x0416,
следующая метка `BE_H_L_LP` 0x042F.

**Десять вызовов на 5807 тиков — это не мелодии, а промотка.** `PlayMelody` крутит
цикл до терминатора `$FF`, и вся мелодия проигрывается ВНУТРИ одного вызова —
мгновенно, потому что заглушка возвращается сразу. То есть Зимин заглушкой сломал
не только звук, но и ТАЙМИНГ: в оригинале на ZX бипер был busy-петлями с `DI`, и
игра честно замирала на время мелодии.

**Возврат к блокирующему проигрыванию — это восстановление аутентики, а не
отклонение.**

## Точка перехвата

Одна: цикл `PlayMelody` в `src/scubacodc.asm`.

    PlayMelody
        LD E,(HL) / LD A,E / INC A / RET Z    ; $FF = конец
        LD D,$00 / INC HL
        LD C,(HL) / INC HL / LD B,(HL) / INC HL
        PUSH BC / EX (SP),HL / PUSH IX
        CALL ROM_BEEPER        <-- сюда
        DI / POP IX / POP HL / JR PlayMelody

К моменту вызова: **HL = X** (высота ноты), **E = длительность** (число периодов),
указатель на мелодию — на стеке. То есть всё нужное уже в регистрах.

Формат ноты в таблицах — три байта: длительность, X младший, X старший.

## Пересчёт частоты — формула уже выверена

Наша i8080-ветка играет ЭТИ ЖЕ мелодии через ВИ53, и `snd_gate` проверяет частоты
с допуском 1%. Формула из `src8080/scubacod0.asm`:

    N = 3X + X/2 - X/16 + 103

Это 3.4375·X + 103 против точного 3.4286·(X + 30.125), где частота бипера ZX
f = 437500/(X + 30.125), а делитель ВИ53 N = 1500000/f. Проверено гейтом:

    X=384 -> N=1423 -> 1054.1 Гц; таблица даёт 1056.4 Гц; разбег 0.22%
    X=256 -> N=983  -> 1525.9 Гц; таблица 1529.1 Гц; разбег 0.20%

**Переносить надо её, а не выводить заново.**

## Развязка оракула

`mkref.py` копирует `src/` в `src_ref/` ДОСЛОВНО (потом лишь подменяет `LD A,R`).
Значит патч под `IFDEF ZXSOUND` попадёт в текст `src_ref`, но **не будет
ассемблирован**: `src_ref` собирается без флага. Разделение достигается флагом
сборки, а не вырезанием текста, — и потому не может рассинхронизироваться.

Обязательное условие: `-DZXSOUND` ставится ТОЛЬКО у отдельной Z80-сборки для
владельца. Ни `src_ref` (оракул), ни `src8080` (наша ветка), ни `build/src`
(его используют гейты старта и титула) флага не получают. Иначе оракул начнёт
блокировать, а наша ветка играет асинхронно — и lockstep умрёт.

## Смета патча

* точка одна, регистры уже несут X и длительность — разбирать ничего не надо;
* пересчёт делителя — перенос готовой формулы, ~25 байт;
* программирование ВИ53: канал 2, порт 9, управляющее слово `0B0h`, режим 3;
  **делитель 0 не выдавать никогда** (счётчик не запустится);
* блокирующее ожидание длительности — по счётчику кадров `FRAMES`, который и так
  крутит прерывание: ждать E кадров;
* молчание в конце — канал 2 в режим 0;
* итого оценочно 60–80 байт кода Z80.

Место: 24 байта мёртвого тела `ROM_BEEPER` + общий запас `cod1` Z80-ветки
(она заметно меньше нашей: 38213 против 44105 байт при том же потолке `$B000`).

## Приёмка, когда будет реализовано

1. гейт частот нот против таблиц мелодий, допуск 1% — по образцу `snd_gate.js`;
2. длительности: снять тайминги титульной мелодии ZX-оригинала в MAME (стенд для
   этого уже есть, `tools/verify/zx/`) и сверить;
3. все десять площадок вызова `PlayMelody` переживают блокирование — в оригинале
   переживали по построению, но проверить наши правки вокруг (джойстик-старт, `im 1`);
4. **lockstep не шелохнулся** — патч вне оракула по построению, но это надо
   подтвердить прогоном, а не рассуждением;
5. полный набор.
