РЕЦЕПТ HEADLESS-ЗАМЕРА ZX-ОРИГИНАЛА В MAME (0.289)

Зачем: калибровать темп нашего порта под ИГРУ 1983 ГОДА, а не под порт Зимина.
Метки порта nzeemin (LExxx) — это адреса ZX-оригинала, поэтому точки счёта
известны без разбора кода: LD9C0=0xD9C0 (игровой цикл), LB213=0xB213 (вызывается
раз за итерацию И в игре, И в демо), LE2A8=0xE2A8 (ныряльщик — только в игре).

Запуск:
  SDL_VIDEODRIVER=dummy mame spectrum -rompath <roms> \
    -cass "Scuba Dive.tzx" -autoboot_script tempo.lua \
    -nothrottle -video none -sound none -seconds_to_run 900
ПЗУ: spectrum.rom = zx48.rom, sha1 5ea7c2b824672e914525d1d5c419d71b84a426a2
(лежит в ~/projects/humphrey-v06c/roms/zx48.rom). Fuse не нужен.
SDL_VIDEODRIVER=dummy ОБЯЗАТЕЛЕН — иначе окно отбирает фокус.

ЧЕТЫРЕ ГРАБЛИ, каждая стоила отдельного захода:
1. Подписки (add_*_notifier, install_read_tap) НАДО держать в живой переменной.
   Локальная умирает вместе со скриптом, сборщик мусора снимает подписку, и
   колбэк перестаёт вызываться через несколько кадров. Симптом: первая печать
   вышла, дальше тишина. Лечится _G.frame_sub = emu.add_...
2. Поле ioport надо выставлять КАЖДЫЙ КАДР всё время удержания: система ввода
   MAME пересчитывает поля покадрово и затирает разовый set_value.
3. Бейсик не принимает клавиши примерно до 250-го кадра после сброса. Раньше —
   нажатия уходят в пустоту. Проверено kbtest.lua: при нажатии с 200-го кадра
   строка 0xBFFE уходит bf->b7 (бит 3 = J), LAST-K(0x5C08)=0xEF = токен LOAD.
   Ни -autoboot_command, ни natkeyboard:post (даже с -natural) до Бейсика не
   доходят вовсе — грузить только матрицей.
4. LOAD "" = клавиша J (режим ключевых слов), затем дважды SYMBOL SHIFT+P, затем
   ENTER; после этого ЛЕНТУ НАДО ПУСТИТЬ САМОМУ: cass:play(), иначе стоит.

Проверка редакции (обязательна перед замером) — байты по адресам меток:
  0xD9C0: cd 13 b2 cd ea bd cd a8 e2   (CALL LB213 / CALL LBDEA / CALL LE2A8)
  0xB213: cd c0 b2                     (CALL LB2C0)
  0xE2A8: dd 21 3b                     (LD IX,DiverObj, DiverObj=LE33B)
Совпало с нашим src_ref — редакция та же.

5. ГЛАВНАЯ: emu.add_machine_reset_notifier НЕ СРАБАТЫВАЕТ — autoboot_script
   запускается уже ПОСЛЕ сброса машины, колбэк не зовётся никогда. Все tap'ы,
   которые я ставил внутри него, не ставились вовсе; отсюда «счётчик молчит»,
   которое я ошибочно списал на то, что tap не ловит опкодную выборку. Ставить
   tap НА ПЕРВОМ КАДРЕ. Проверка: taptest.lua даёт 59686 выборок 0x15E1 за 200
   кадров (холостой цикл ПЗУ).
6. Пространство для выборки команды — "opcodes", не "program".
7. Демо-режим выходит в меню по ЛЮБОЙ клавише: жать один раз и больше не трогать,
   иначе игра так и стоит в меню (PC приклеен к 0xEE2F).

РАСКЛАДКА КЛАВИШ ОРИГИНАЛА (разобрана по дизассемблеру, не подбором)
============================================================================
Как получено: dump.lua снимает 0x4000..0xFFFF в момент, когда PC=0xEE2F (меню),
дальше z80dasm по нужному куску:
  python3 -c "d=open('scuba_menu.bin','rb').read(); \
    open('c.bin','wb').write(d[0xEDF0-0x4000:0xEF70-0x4000])"
  z80dasm -a -t -g 0xEDF0 c.bin

СТАРТ ИГРЫ И ВЫБОР УРОВНЯ — ОДНА И ТА ЖЕ КЛАВИША '1'..'4':
  ee2c  cd ad ee   call 0eeadh      ; проверка «пора ли в демо»
  ee2f  3a 05 5c   ld a,(05c05h)    ; KSTATE+5, счётчик ПЗУ по новой клавише
  ee32  fb         ei
  ee33  b7         or a
  ee34  28 f6      jr z,0ee2ch      ; <-- сюда и залипал PC прошлого захода
  ee36  3a 08 5c   ld a,(05c08h)    ; LAST-K, ASCII нажатой клавиши
  ee39  fe 4b      cp 04bh          ; 'K' = переопределение клавиш (call 0ec7ch)
  ee45  fe 4c      cp 04ch          ; 'L' = отдельная ветка с запросом Y/N
  ee7d  d6 31      sub 031h         ; LAST-K - '1'
  ee7f  38 9b      jr c,0ee1ch      ; меньше '1' => назад в цикл меню
  ee81  fe 04      cp 004h
  ee83  30 97      jr nc,0ee1ch     ; больше '4' => назад в цикл меню
  ee85  3c         inc a
  ee86  32 10 5b   ld (05b10h),a    ; LEVEL := 1..4
  ee89..ee9d       мелодия, обнуление 5B46/5B48
  ee9e  cd 90 d9   call 0d990h      ; Game
Никакого отдельного «старта» нет: цифра И задаёт уровень, И запускает игру.
'1'..'4' в матрице ZX — полуряд 0xF7FE, в MAME это порт :LINE3, поля "1".."4".
Хватает короткого нажатия (10 кадров): 0x5C05 ПЗУ взводит на новой клавише.

УПРАВЛЕНИЕ В ИГРЕ — ПЕРЕОПРЕДЕЛЯЕМАЯ ТАБЛИЦА 0x5B38..0x5B43, читается напрямую
портами в 0xE2DB (вызывается из обработчика ныряльщика 0xE2A8 раз в 20 кадров,
счётчик IX+0x20 перезаряжается значением 0x14):
  e2e3  ed 4b 38 5b  ld bc,(05b38h) ; адрес порта
  e2e7  3a 3a 5b     ld a,(05b3ah)  ; маска
  e2eb  ed 78        in a,(c)
  e2ed  a2           and d
  e2ee  20 01        jr nz,+1
  e2f0  1c           inc e          ; направление += 1
  ...аналогично 0x5B3B -> dec e, 0x5B3E -> dec (ix+0eh), 0x5B41 -> inc (ix+0eh)
Байты таблицы в свежезагруженной игре (значения по умолчанию):
  5B38 = FE FE 04 -> порт 0xFEFE бит2 = X            поворот «+»
  5B3B = FE FE 02 -> порт 0xFEFE бит1 = Z            поворот «-»
  5B3E = FE 7F 01 -> порт 0x7FFE бит0 = SPACE        ГАЗ    (IX+0Eh -1, предел 8)
  5B41 = FE 7F 02 -> порт 0x7FFE бит1 = SYMBOL SHIFT ТОРМОЗ (IX+0Eh +1, предел 0x14)
IX+0Eh — делитель кадров ныряльщика: 8 = быстро, 0x14 = медленно. В MAME это
поля :LINE0 "x"/"z" и :LINE7 "SPACE"/"SYMBOL SHIFT".

ЕЩЁ ГРАБЛИ (заход про настоящую игру):
8. Ныряльщик под скриптованным вводом гибнет за 5-10 с, три жизни — и снова
   меню. Скрипт обязан САМ перезапускать игру (снова жать цифру) и выбрасывать
   окно, на котором игра кончилась. Признак «мы в игре» — растёт счётчик 0xE2A8.
9. Тик 0xB213 идёт ИЗ ДВУХ мест: тело игрового цикла 0xD9C0 (call B213/BDEA/E2A8,
   возврат jr $-25 с 0xD9D9) и такая же тройка в ветке смерти/перехода уровня с
   0xD9F7. Поэтому в окнах, где «цикл» заметно меньше «тика», шла смерть/рестарт
   уровня — и темп там ПАДАЕТ до 92-110 тик/с.
10. Уровень реально применён — проверять по счётчикам записей 0x5B15..0x5B19:
   уровень 1 = 27/18/26/5/12, уровень 4 = 51/30/50/20/57.
11. Принудительная запись направления (DiverObj+6 = 0xE341) НЕ помогает увести
   ныряльщика вглубь: он гибнет у поверхности, экран так и остаётся строкой 0
   мини-карты. Глубокая сцена (строка 5) достижима только в демо — 0xEEAD сам
   ставит (0x5B03)=0x0518.
